# 第 7 页 · 调参口诀

## 一句话调参口诀

```
基线要够、匹配要清、误差要滤；小基线就别指望深度准。
```

## 参数速查表

| 参数 | 含义 | 推荐值 | 调大效果 | 调小效果 |
|------|------|--------|----------|----------|
| reproj_thresh | 重投影误差阈值 | **1~3 px** | 保留更多点但含坏点 | 点更少但更干净 |
| min_depth | 最小深度 | **>0** | 剔远点 | 保留远点 |
| 方法 | DLT / 中点法 | **DLT** | — | — |

## 实战技巧

### 和本质矩阵串联

E 分解得到位姿 → 三角化建初始点云 → 光束法平差联合优化。

### 双目立体

立体匹配得到视差后，三角化把视差换算成深度，即深度图。

### 质检习惯

三角化后一定打印重投影误差分布，误差中位数 >2 像素说明前端匹配有问题。

## 性能参考

| 条件 | 耗时 | 说明 |
|------|------|------|
| 100 对点 DLT | ≈0.5 ms | cv2.triangulatePoints |
| 10000 对点 | ≈50 ms | 批量线性 |
| 含重投影过滤 | ≈1.3× | 额外校验开销小 |

## 选型建议

**适合用**：SfM 建点云、双目立体恢复深度、SLAM 地图点生成、AR 锚点定位

**不适合用**：对噪声与基线长度敏感、小基线（近纯旋转）时深度极不稳、需准确的相机位姿

::: tip 一句话
两条「视线」在空间里交于一点——那个交点就是场景点的 3D 位置
:::

## 🎯 三角化的 4 个坑

1. **必须先做相机标定**：内外参错 1%，深度就错 5%+；
2. **点必须在两视图上都可见**：被遮挡的点不能三角化；
3. **要做 cheirality check**：三角化出的点必须在两个相机**前方**（深度为正），否则是错误解；
4. **远景点不要硬三角化**：三角化后做重投影误差检查，误差 >1px 的点扔掉。

### OpenCV 调用

```python
P1 = K @ np.hstack([R1, t1])  # 相机1投影矩阵 3×4
P2 = K @ np.hstack([R2, t2])
points4d = cv2.triangulatePoints(P1, P2, pts1.T, pts2.T)
points3d = (points4d[:3] / points4d[3]).T  # 齐次坐标转非齐次
```
（注意：OpenCV.js 构建不带 `triangulatePoints`，请在 Python/C++ 环境使用）
