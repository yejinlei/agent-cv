# 核心概念 · 霍夫变换

> 读懂 5 个概念，你就彻底懂了霍夫变换为什么能从一堆噪声边缘里"投票"出直线。

## 1. 参数空间与图像空间（对偶性）

**图像空间**（image space）：$(x, y)$，就是像素坐标，直线是"直的东西"。
**参数空间**（parameter space）：表示直线的参数。

核心思想：**点 ↔ 曲线的对偶**。

| 图像空间 | 参数空间（Duda-Hart 极坐标）|
|---|---|
| 一个边缘点 $(x_0,y_0)$ | 一条正弦曲线 $\rho = x_0 \cos\theta + y_0 \sin\theta$ |
| 多个点在一条直线上 | 多条正弦曲线在 $(\rho_0,\theta_0)$ 交汇 |
| 一条直线 $(\rho_0,\theta_0)$ | 参数空间里的一个点 |

**白话**：想象你是一个站在某个边缘像素上的小人，你要回答"所有可能穿过我的直线是哪些"——就是正弦曲线上的所有 $(\rho,\theta)$。同一条真实直线上的所有小人都会在同一个 $(\rho,\theta)$ 相遇，那个相遇点票数最高，就是直线。

## 2. 极坐标参数化（Duda-Hart 公式）

直线用极坐标表示：

$$\rho = x \cos\theta + y \sin\theta$$

其中：
- $\theta$：直线**法线方向**（不是直线本身方向！），范围 $[0, \pi)$（或 $[-90°, 90°]$）
- $\rho$：**原点到直线的垂直距离**，范围 $[-\rho_\max, \rho_\max]$，$\rho_\max = \sqrt{W^2 + H^2}$（图像对角线长度）

**为什么不能用 $y=kx+b$**：
- 垂直直线 $k = \infty$，没法表示
- 近垂直直线 $k$ 极大，累加器存储不现实
- $\theta \in [0,\pi)$ 有界，$\rho$ 有界，累加器大小可预估

**直觉**：极坐标是"用垂线方向 + 距离"描述直线，任何方向都能表示，且参数范围都有限。

## 3. 累加器投票（accumulator）

累加器 $A[\rho_\text{bin}, \theta_\text{bin}]$ 是一张二维直方图，初值全 0。

**投票过程**：
1. 遍历所有边缘像素 $(x,y)$（通常是 Canny 输出）
2. 对每个 $\theta_k$，算 $\rho_k = x \cos\theta_k + y \sin\theta_k$
3. 把 $\rho_k$ 量化到最近的 bin，对应单元 $A[\rho_\text{idx}, k]$ 加 1
4. 遍历完成后，找 $A$ 里**局部极大值**，且超过阈值 $T$ 的 bin —— 就是直线参数

**白话**：像开选举，每个边缘点是选民，给它经过的每个 $(\rho,\theta)$ 候选直线投一票，开票后票数高的当选。

### 累加器分辨率（很关键！）
- $\Delta\theta$ 太大：角度分辨率粗，可能把两条近似直线合并；
- $\Delta\theta$ 太小：同一条直线会分散到多个 $\theta$ bin，峰值被"稀释"；
- $\Delta\rho$ 同理。

**OpenCV 默认**：
- `rho = 1`（1 像素分辨率）
- `theta = π/180`（1° 分辨率）

### 为什么还要 NMS（非极大抑制）
一条真实直线在累加器里会形成一个"峰团"——一个主峰 + 周围一圈次峰（量化误差导致），所以必须做 NMS（邻域取最大），避免同一条直线被重复检测出多条。OpenCV `HoughLines` 内部会做基本 NMS，但参数敏感，有时要二次 NMS。

## 4. 概率霍夫 PHT / PPHT（为什么 P 版快）

**标准 HT（SHT）问题**：必须遍历所有边缘点，对每个点遍历所有 $\theta$ bin，复杂度 $O(N_\text{edges} \cdot N_\theta)$；高分辨率图像边缘点可能 10 万级别，很慢。

**PHT（Probabilistic HT，Kiryati 1991）**：随机抽 $m$ 个边缘点投票（$m \ll N_\text{edges}$），只要 $m$ 足够大，峰值仍能可靠检测——典型加速 3–5 倍。

**PPHT（Progressive PHT，Matas 1998）**：更进一步：
1. 随机抽一个边缘点投票
2. 若某个 bin 票数过阈值 → **立刻沿该方向在图像里做边缘行走（walk）找线段端点**
3. 输出这条线段，并把属于它的所有边缘点从投票池**移除**
4. 重复 1–3

结果：
- 速度 **5–10 倍**提升
- 直接返回线段**两个端点**（SHT 只返回 (ρ,θ) 无限长直线）
- **OpenCV `cv2.HoughLinesP` 就是 PPHT**（注意 P 是 Progressive，不是 Probabilistic）

## 5. 圆霍夫变换（CHT，Circle Hough Transform）

圆的方程比直线多一个参数：

$$(x - a)^2 + (y - b)^2 = r^2$$

- $(a,b)$：圆心坐标
- $r$：半径

**三维累加器问题**：如果直接按圆方程投票，累加器是 $A[a, b, r]$ 三维的——速度和内存都是灾难（$O(N_\text{edges} \cdot N_a \cdot N_b \cdot N_r)$）。

**梯度方向降维（OpenCV 做法）**：
1. 用 Sobel 算每个边缘点的梯度方向 $\nabla I$，圆的**半径方向 = 梯度方向**（法线方向过圆心）
2. 每个边缘点沿梯度正反方向各投票一条线上的圆心候选 → 累加器从 3D 降到 2D（圆心 a,b）
3. 圆心确定后，再在半径维 $r$ 投票 → 2D 圆心累加器 + 1D 半径投票
4. 这叫 **"2-1 Hough Transform"（21HT，Yuen 1990）**，速度快一个数量级

**白话**：直线每个边缘点要投一条正弦曲线（1D 搜索），圆每个边缘点只沿法线方向投一条线（2D 里的 1D 搜索），效率大幅提升。

**OpenCV `HoughCircles`** 实现的就是 21HT，参数：
- `dp`：累加器分辨率相对图像分辨率的反比（dp=1 同分辨率，dp=2 半分辨率，更快更粗）
- `minDist`：两圆心最小距离（避免同圆多次检出）
- `param1`：Canny 高阈值（内置 Canny，低阈值自动设为高阈值一半）
- `param2`：圆心累加器阈值（越小检测越多假圆）
- `minRadius` / `maxRadius`：半径搜索范围

## 6. 广义霍夫变换 GHT（任意形状）

直线/圆有显式方程，任意形状怎么办？Ballard 1981 提出 GHT：

1. **训练阶段**：给定模板形状，选一个参考点（比如重心），对每个边缘点存「**该边缘点的方向 $\phi$ → 到参考点的位移向量 $(r,\alpha)$**」，存进一张 R-table（查表）。
2. **检测阶段**：对每个边缘点，根据它的方向查 R-table，给所有可能的参考点位置投票；累加器峰值就是参考点，即形状位置。

白话：R-table 就是"形状的投票指南"，每个边缘点按指南给"参考点应该在哪"投票。

**局限**：
- 对旋转/缩放敏感（要扩维或旋转 R-table）
- 现在基本被深度学习目标检测取代
- 仍是"形状检测 = 投票"思想的源头

## 7. 几个反直觉点

1. **霍夫变换的输入必须是二值边缘图**，不是灰度图。直接给灰度图没意义——投票要的是"这里可能是边缘"。
2. **HoughLinesP 输出的是直线段两端点，但端点位置不一定精确**，只保证线段上边缘点密度够高。想精确端点要自己延长/截短到图像边界或边缘末端。
3. **ρ 可能是负数**：当直线法线指向第二、三象限时 ρ 为负，这是正常的（等价于 $\theta + \pi, -\rho$）。
4. **阈值 T 没有绝对标准**，它等于"至少有多少个边缘点在同一条直线上"，和图像分辨率/边缘密度强相关，必须现场调。
5. **HoughCircles 的输出是浮点圆**，检测到的圆心/半径不是整数像素——这是因为累加器插值和亚像素定位。

## 术语速查

| 术语 | 解释 |
|---|---|
| ρ (rho) | 原点到直线的垂直距离（像素）|
| θ (theta) | 直线法线方向（弧度），范围 [0, π) |
| 累加器 accumulator | 二维/三维直方图，记录每个参数候选得到的票数 |
| 局部极大值 local maxima | 累加器中比周围都高的 bin，对应真实形状 |
| PPHT | Progressive Probabilistic HT，渐进概率霍夫，OpenCV HoughLinesP |
| 21HT | Two-One Hough Transform，圆霍夫的梯度降维版，OpenCV HoughCircles |
| GHT | Generalized HT，广义霍夫，任意形状检测 |
| R-table | GHT 的查表，存边缘方向→参考点位移 |
| NMS | 非极大值抑制，消除重复检测 |
