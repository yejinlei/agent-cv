# 踩坑指南 · 霍夫变换

> 霍夫是"参数敏感"的典型代表。10 个最常见的坑，每个都能让你调一下午。

## 坑 1：没做 Canny，直接把灰度图传给 HoughLines

**症状**：结果为空 / 检测到几千条线 / 整图都是线。

**原因**：Hough 要求输入是**二值边缘图**（非零像素视为边缘点），直接给灰度图会把所有非零像素都当边缘点。

**解决**：
```python
edges = cv2.Canny(cv2.GaussianBlur(gray, (5,5), 1.0), 50, 150)
lines = cv2.HoughLinesP(edges, ...)
```

**例外**：`HoughCircles` **自带 Canny**（param1 控制高阈值），直接传灰度图即可；传 Canny 结果反而可能干扰内置流程。

---

## 坑 2：Canny 阈值错，边缘图满屏噪点

**症状**：检测出几十上百条线，几乎全是假的；或者根本检测不到线。

**原因**：
- Canny 低阈值过低 → 大量噪声边缘被检出 → Hough 被噪声点污染
- Canny 高阈值过高 → 真直线边缘断裂 → Hough 票数不够

**诊断**：**先单独看 Canny 输出！** 90% 的 Hough 调参问题都是 Canny 的锅。

**解决**：
- 调 Canny 阈值到"真直线是连续的，背景只有零星噪点"的状态
- 典型值：`(30, 100)` 到 `(80, 200)`，根据图像对比度现场调
- 高斯模糊核 3×3 或 5×5 可以显著减少噪点

---

## 坑 3：threshold 设太大 → 什么都检测不到

**症状**：`lines is None` 或只有 1–2 条线。

**原因**：threshold 表示"至少多少个边缘点共线才算一条直线"。如果 Canny 边缘密度低，或者线段短，票数达不到阈值。

**诊断**：先把 threshold 调小到 30 看看；如果这时出很多线，说明是阈值高了。

**解决**：
- 先保证 Canny 边缘是连续的
- threshold 一般从 50 开始调，根据 ROI 内边缘密度调整
- 图像大、线长 → threshold 大；图像小、线短 → threshold 小

---

## 坑 4：threshold 设太小 → 满屏假线

**症状**：输出几百上千条线段，大量是斜的/短的噪声线。

**原因**：随机噪声点也能凑够几票形成假峰值。

**解决**：
- 提高 threshold
- **加 `minLineLength` 过滤短线**（极有效！）
- ROI 裁剪只保留感兴趣区域
- 提高 Canny 高阈值，减少噪声边缘

👉 **threshold + minLineLength + ROI 三件套**能消灭 80% 的假阳性。

---

## 坑 5：maxLineGap 理解错

**症状**：长直线被切成几段短的；或两个不相关的边缘被连成一条线。

**原因**：很多人以为 maxLineGap 是"两个点之间最大距离"，其实它是**行走时允许的连续空隙像素数**——即线段中间断了这么长，仍然算同一条线。

- **太大**：会把不相关的边缘错误连接
- **太小**：长直线在边缘断裂处被截断

**建议**：
- PCB 走线、文档线等精细场景：3–5
- 车道线、外轮廓等允许断裂：10–20
- 边缘质量差的视频：20–40

---

## 坑 6：rho/theta 分辨率设太细，峰值被稀释

**症状**：明显的直线检测不出来，threshold 调低也没用。

**原因**：Δθ 从 1° 改到 0.1°，同一条直线的票会分散到 10 个 bin 里，每个 bin 票数都达不到阈值。

**经验值**：
- `rho=1, theta=π/180`（1°）是**绝大多数场景的最优默认值**
- 需要精确角度时再考虑 `theta=π/360`（0.5°），同时 threshold 也要相应降低
- `rho=0.5` 通常没有必要，像素级已经足够

---

## 坑 7：不做 ROI，整图检测 → 又慢又乱

**症状**：车道线检测里检测到天空的电线杆、对向车道的线、路边建筑的边。

**原因**：Hough 是全局算法，它不"理解"图像语义，只会找所有共线边缘。

**解决**：
- **车道线**：只检测图像下半部分（路面）
- **文档倾斜**：只检测水平/垂直方向（角度过滤）
- **PCB 走线**：先二值化提取走线层，再做 Hough
- **工业检测**：用 ROI 掩膜裁剪到工件区域

ROI 裁剪不仅**大幅提速**（边缘点减少 70%+），还能**消灭大量假阳性**。

---

## 坑 8：HoughCircles 的 dp/minDist 设错 → 同圆多次检出或漏检

**症状**：
- dp=1 + minDist 小 → 一个圆被检测成多个同心圆
- dp=2 + minDist 大 → 靠近的两个圆被合并成一个

**解决**：
- `dp` 一般 1–1.5 之间；对大图像/实时场景 2 更快
- `minDist` 应该 ≥ 圆的直径（按 `minRadius*2` 估）
- 圆心距离小于 minDist 时，只保留票数最高的那个

```python
# 典型：硬币检测
circles = cv2.HoughCircles(gray, cv2.HOUGH_GRADIENT,
                           dp=1.2, minDist=40,
                           param1=100, param2=35,
                           minRadius=15, maxRadius=35)
```

---

## 坑 9：HoughCircles 的 param2 设太小 → 一堆假圆

**症状**：输出几十个圆，甚至在没有圆的地方也检测到圆。

**原因**：`param2` 是圆心累加器阈值，和 HoughLines 的 threshold 一样——越小越"宽松"。

**诊断**：把 param2 调到 50 左右看看；如果这时几乎没圆，说明 param2 可能要在 30–50 之间找平衡点。

**建议起点**：
- 图像清晰、圆明显：param2=40–50
- 图像一般：30–40
- 圆边缘不连续/弱：20–30（会有假圆，需要后处理过滤）

---

## 坑 10：不做后处理过滤，直接信任输出

**症状**：
- 车道线检测出了几十条线，包括横向的裂缝、阴影
- 圆检测出了不圆的圆、离工件很远的圆
- 直线段有重复检测（同一条线被检出两次）

**解决**——后处理三板斧：

**① 角度过滤**：
```python
angle = np.degrees(np.arctan2(y2-y1, x2-x1))
if not (20 < abs(angle) < 70):   # 只要斜 20°–70° 的（车道线）
    continue
```

**② 长度过滤**：
```python
length = np.hypot(x2-x1, y2-y1)
if length < min_len: continue
```

**③ 位置过滤**：
```python
cx, cy = (x1+x2)/2, (y1+y2)/2
if cx < W*0.1 or cx > W*0.9: continue   # 去掉边缘的线
```

**④ NMS 去重**：相似的直线段合并（角度差 < 5° 且 距离 < 5 像素视为同一条）。

## 症状 → 原因速查表

| 症状 | 可能原因（对应坑号）|
|---|---|
| `lines is None` | 坑 1/2/3/6 |
| 几百条假线 | 坑 2/4/7 |
| 长直线被截断 | 坑 5（maxLineGap 太小）|
| 不相关边被连一起 | 坑 5（maxLineGap 太大）|
| 一个圆检测成多个 | 坑 8（minDist 太小）|
| 近邻圆被合并 | 坑 8（minDist 太大/dp 太大）|
| 一堆假圆 | 坑 9（param2 太小）/ 坑 1（没传灰度）|
| 漏检短线段 | 坑 3（threshold 大）/ minLineLength 大 |
| 运行很慢 | 坑 7（没做 ROI）/ rho/theta 太细 |
| 同样参数两次结果不同 | PPHT 随机抽样（设 RNG seed）|

## 诊断 Checklist（9 步走）

每次调 Hough 不工作时，按这个顺序排查：

1. ✅ 看原图：图像清晰吗？有明显直线/圆吗？
2. ✅ 看灰度图：`cvtColor` 是否正确？
3. ✅ 看 Canny 输出（HoughLines）：边缘是不是"连续不断、噪声少"？
4. ✅ 看模糊：是否先做了 Gaussian/median 模糊？
5. ✅ 做 ROI：有没有裁掉不需要的区域？
6. ✅ 调低 threshold/param2：如果调低后出线，说明阈值高了
7. ✅ 调 Canny：阈值太高导致边缘断裂，或者太低导致满屏噪点
8. ✅ 加 minLineLength/minDist：过滤短假线/假圆
9. ✅ 做后处理：角度/长度/位置过滤 + NMS 去重

## 性能坑

| 场景 | 原因 | 解决 |
|---|---|---|
| 1080p 视频跑 HoughLinesP 只有 10fps | 整图 Canny + Hough | ROI 裁剪 + 降分辨率到 640×360 |
| HoughCircles 特别慢 | minRadius 太小、maxRadius 太大 | 缩小半径范围、dp=2 |
| Python 手写 HT 慢得离谱 | Python 循环 | 生产一律用 OpenCV C++ 实现 |

## 最容易搞混的几件事

1. **HoughLines 的返回是无限直线参数 (ρ,θ)**，HoughLinesP 返回线段端点 (x1,y1,x2,y2) —— **99% 场景用 P 版本**
2. **HoughCircles 不需要先 Canny**，它内置 Canny；传彩色图会报错
3. **HoughCircles 输出是浮点 (x,y,r)**，要转 int 才能在图像上画
4. **θ 的范围是 [0, π) 或 [-π/2, π/2)**，取决于 OpenCV 版本参数；HoughLines 的 min_theta/max_theta 默认是 [0, π]
5. **ρ 可以是负数**，这是正常的（法线朝左/下方向时为负），画直线时要用完整公式，不要取绝对值
