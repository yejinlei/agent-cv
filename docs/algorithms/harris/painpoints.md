# 常见坑与踩雷指南

> Harris 是简单算法，但简单算法最容易栽在"它为什么没检出 / 为什么检出一堆假点"这类细节里。

## 坑 1：没转 float32 → R 值全错

**症状**：阈值化后要么全白要么全黑，几乎看不到红点点，或者只在高对比边缘有零星响应。

**原因**：`cv2.cornerHarris` 内部用 CV_32F 做累加，如果直接传 uint8，`Ix² = (uint8) * (uint8)` 会溢出（255²=65025 超出 uint8 上限 255，结果截断）。

**修法**：

```python
gray_f = np.float32(gray)            # ✅
R = cv2.cornerHarris(gray_f, 2, 3, 0.04)
```

## 坑 2：用固定阈值 → 每张图都要重新调

**症状**：换张图片检测结果差十万八千里，要么点太多噪声大，要么几乎没有点。

**原因**：R 的数量级和图像整体对比度正相关——亮图 R 值量级大、暗图小。

**修法**：永远用**相对阈值** `thresh_ratio * R.max()`，thresh_ratio 从 0.01 起步：

```python
R[R > 0.01 * R.max()]                # ✅ 相对阈值
# R[R > 10000]                       # ❌ 固定阈值，换图就废
```

## 坑 3：忘记做高斯预平滑 → 噪点全当角点

**症状**：图上密密麻麻全是红点，尤其在纹理粗糙、有颗粒噪点的区域。

**原因**：Sobel 对噪声非常敏感——一个椒盐噪点会让局部梯度剧变，M 矩阵两个 λ 都大，R 值就大。

**修法**：调用 Harris 前先做一次高斯平滑：

```python
gray = cv2.GaussianBlur(gray, (5,5), 1.4)   # ✅
```

参数怎么选：σ 越大噪点压得越狠，但真实角点也会被磨圆。1.4 是比较均衡的起点；图像噪点大可以加到 2.0。

## 坑 4：blockSize 选错 → 要么漏点要么团簇

**症状**：
- `blockSize=2`：检测出的角点分布很碎，一个真实角点出好几个点
- `blockSize=7+`：多个挨得近的角点被合并成一个大团，棋盘格内角丢失

**原因**：blockSize 决定了 M 矩阵求和窗口大小——窗口太小不够"整体"，太大把多个角点混在一起。

**调法表**：

| 场景 | blockSize |
|---|---|
| 棋盘格/高精度标定 | **2 或 3** |
| 一般场景 / 跟踪初始化 | **3**（默认）|
| 大结构角点（建筑、几何物体）| **5** |
| 粗糙的大尺度角点 | 7 |

## 坑 5：k 值乱调 → 点多就是 0.02，点少就是 0.06

**症状**：很多人知道 k=0.04 是默认值，但不知道什么时候该改。

**修法**：按"你想要多少角点"来：

| 目的 | k |
|---|---|
| 只保留最强角点（标定板）| **0.05–0.06** |
| 一般场景 | **0.04**（默认）|
| 点不够多、跟踪要稳定 | **0.02–0.03** |
| <0.02 | 危险，边缘会被误判为角点 |

**物理含义**：k 越小，R = λ₁λ₂ - k(λ₁+λ₂)² 越容易为正——判定角点的门槛越低。

## 坑 6：不做 NMS → 每个角点变成一团红点

**症状**：每个角点周围 3×3 到 5×5 区域都被染红，看起来是"红点团"而不是单个点。

**原因**：角点响应是连续分布的，真正的角点附近 R 值都高——必须只保留局部最大值。

**修法**：

```python
# OpenCV 一行 NMS（用 dilate 取邻域最大值）
R_dilated = cv2.dilate(R, None)
corners_mask = (R > 0.01*R.max()) & (R == R_dilated)
```

或者**直接用 `cv2.goodFeaturesToTrack`**——它内部已经做了 NMS 和 minDistance 过滤，最省心。

## 坑 7：没有尺度不变性 → 远近角点响应差异巨大

**症状**：拍远处棋盘格能检到，走近了同一个棋盘格角点检不出（或反过来）。

**原因**：Harris 窗口是固定像素尺寸——远处一个 5×5 窗口覆盖了棋盘格一个完整格子，走近了 5×5 只覆盖格子里的一条边。

**这不是 bug，是 Harris 的本质局限**。修法有三种：

1. **多尺度 Harris（Harris-Laplacian）**：在图像金字塔每层都跑 Harris，选尺度空间极值
2. **直接用 SIFT/SURF/ORB**：它们都内置了尺度空间
3. **固定拍摄距离**：工业场景相机和工件距离固定时这个问题不存在

## 坑 8：角点坐标"漂移"1–2 像素 → 标定误差大

**症状**：用 Harris 角点做棋盘标定，重投影误差 0.5 像素以上下不来。

**原因**：整数像素精度不够，实际角点位置通常在两个像素之间。

**修法**：用 `cv2.cornerSubPix` 做亚像素精化（见 [source.md](./source#三shi-tomasi--亚像素定位标定跟踪标配)），精度能到 0.01 像素，标定误差能降到 0.1 像素以下。

## 坑 9：对重复纹理/边缘交叉误检

**症状**：窗格、铁丝网、瓷砖接缝处检出大量"假角点"。

**原因**：这些位置两个方向确实都有梯度变化，但实际没有物理意义上的"角"。

**修法**：
- 提高 qualityLevel（从 0.01 提到 0.03）
- 加大 minDistance（从 10 提到 20）
- 后续用描述子（SIFT/ORB）再筛一遍，或用 RANSAC 在几何阶段剔除
- 标定场景**永远用 `findChessboardCorners`**，不要自己写 Harris 找棋盘

## 坑 10：彩色图直接传 → 报错或错误

**症状**：`cv2.error: (-215) src.type() == CV_8UC1 || src.type() == CV_32FC1`。

**修法**：**必须先转灰度**：

```python
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
```

Harris 是灰度算子，没有任何"彩色 Harris"的标准做法——彩色信息对梯度角点检测没帮助。

## 踩坑速查表

| 症状 | 最可能的原因 | 修法 |
|---|---|---|
| 几乎没有点 | dtype 错 / 阈值太高 | 转 float32，thresh_ratio 降到 0.005 |
| 全是红点 | 没做高斯平滑 / thresh 太低 | GaussianBlur，thresh 升到 0.02 |
| 角点变成一团 | 没做 NMS | dilate + 比较，或用 goodFeaturesToTrack |
| 远近都要检出 | 没有尺度不变 | 用图像金字塔 / 换 SIFT/ORB |
| 标定误差大 | 没用亚像素 | cornerSubPix |
| 边缘上一堆假点 | k 太小 / 阈值太低 | k 调到 0.05，qualityLevel 调高 |
| 棋盘格角点丢失 | blockSize 太大 | blockSize=2 或 3 |
