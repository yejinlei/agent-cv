# DPM 调参技巧

## ① 部件数（numparts）

部件数是 DPM 最关键的结构参数。

| 类别 | 部件数 | 备注 |
|---|---|---|
| 行人 | **8** | voc-release5 默认配置 |
| 车辆 | 6~8 | 正/侧面都需要 |
| 动物 | 8 | 肢体多，需要更多部件 |
| 瓶子/杯子/标志 | 3~4 | 刚性物体部件少即可 |
| 自行车 | 8 | 双轮 + 车身 + 把手 |

**心法**：从 8 开始，观察训练后的部件可视化——如果某两个部件总是重叠或死区（权重接近 0），说明部件太多；如果某些形变模式没覆盖到，可以加。

## ② Component 数（混合模型）

| 场景 | component 数 |
|---|---|
| 只有正面（如正面人脸） | 1 |
| **行人（正/侧/背）** | **3** |
| 车辆（多视角） | 4~6 |
| 家具/复杂物体 | 6~8 |

voc-release5 训练脚本默认用**根滤波器聚类**自动发现 component，也可以手动指定。**如果数据集中某个视角不足 50 张正样本，那个 component 会训不好**。

## ③ HOG 参数

| 参数 | 默认 | 调优建议 |
|---|---|---|
| cell 大小 | 8×8 px | 通用不改；小目标可用 6 px |
| block 大小 | 2×2 cell | 不改 |
| 方向 bin | 18（9 无符号+9 对比敏感+4 纹理）| 不改，voc-release5 的 32 维是经验最优 |
| 金字塔间隔 | 10 层/octave | 小目标多→12~16；速度优先→8 |

## ④ SVM 正则化 C

| 场景 | C |
|---|---|
| 训练数据少（几百张） | 0.001 |
| **默认** | **0.002~0.01** |
| 训练数据多（上万张） | 0.01 |

C 大：模型拟合数据紧，可能过拟合；C 小：正则化强，模型保守。

## ⑤ 检测阈值（threshold）

voc-release5 默认阈值 `-0.5`（注意是负的，因为 SVM 分数本身经过偏置平移）：

| 阈值 | 检测率 | 误检率 | 适用 |
|---|---|---|---|
| -1.0 | 高（多检） | 高 | 召回优先 |
| **-0.5** | **中** | **中** | **默认** |
| 0.0 | 中 | 低 | 精度优先 |
| 0.5+ | 低（漏检） | 极低 | 高置信筛选 |

实战中一般**用 precision-recall 曲线选阈值**，不要用默认 -0.5 硬卡。

## ⑥ NMS 阈值

| overlap 阈值 | 效果 |
|---|---|
| 0.2 | 激进，相邻框合并多（稀疏场景） |
| **0.3** | **DPM 论文默认** |
| 0.5 | 宽松，密集目标保留多（人群/停车场） |

如果多 component 重复检测同一目标，可以额外按 class 再做一次 NMS。

## ⑦ 难负样本挖掘（Bootstrap）轮数

| 轮数 | 效果 |
|---|---|
| 1~2 | 欠拟合，假阳多 |
| **3~5** | **通常够** |
| 6+ | 可能过拟合，且训练时间爆增 |

每轮挖掘会把所有"被误判成正"的负窗加入训练集。训练日志里观察：如果新增难负样本数量 < 100，说明收敛了，可以停。

## ⑧ 典型场景参数模板

### 模板 A：INRIA 行人检测（voc-release5 默认）
```matlab
% globals
interval = 10;         % 金字塔层数/octave
numparts = 8;          % 部件数
note = 'INRIA person';
% 训练
model = pascal_train('person', note);
% component 数自动，初始 1 训练后聚类为 3
```

### 模板 B：刚性物体（如交通标志）
```matlab
% 部件少、component 少
numparts = 4;
% 手动指定单一 component
model = root_model(cls, pos, note, 8, []) % 单 component 训练
% 不用混合模型聚类
```

### 模板 C：多视角车辆
```matlab
% 正样本包含正面/侧面/背面多视角
% 训练后聚类为 6 component
% 部件数 8
numparts = 8;
% 开左右翻转增强
pos = point_flip(pos);  % voc-release5 内置翻转工具
```

### 模板 D：速度优先（级联 DPM）
voc-release5 之后作者发布了 cascade DPM（星型模型级联）：
```matlab
% 训一个普通 DPM 模型后，再额外做级联压缩
csc_model = cascade_model(model, 'pedestrian', 2010, 0);
% 检测用 csc_model，速度快 10-20 倍
[ds, bs] = cascade_detect(im, csc_model, csc_model.thresh)
```

## ⑨ 检测加速套路

1. **缩图检测**：大图先缩到 50%~70% 再检，等比放大框
2. **设 min/max size**：不跑明显超出目标尺寸的尺度
3. **跳帧 + 跟踪**：视频中检测频率降到 5~10 FPS，中间帧用 KCF/MOSSE 跟踪
4. **级联模型**：用 cascade 版 DPM（作者后期工作），速度 10~20 倍
5. **ROI 限定**：只在感兴趣区域（如路面）检测
6. **GPU 加速**：有 CUDA 实现版本，速度再快一个量级

## ⑩ 与其他检测器选型对照表

| 需求 | 选什么 |
|---|---|
| 快速刚性物体检测（人/脸） | HOG+SVM 或 Viola-Jones |
| 形变目标（行人/动物）传统方法 | DPM（仅当不能用深度学习时） |
| 实时（>10 FPS） | **不要用 DPM**，直接 YOLO/SSD |
| 教学/研究部件模型思想 | DPM 是必读经典 |
| 工业落地（2024+） | YOLOv8 / YOLOv11 / RT-DETR |
| 可解释性需要看部件响应 | DPM 的部件可视化比 CNN 直观 |
| CPU 低算力（树莓派等） | HOG+SVM 或轻量 CNN（NanoDet） |

## ⑪ 什么时候应该放弃 DPM，直接上深度学习

满足以下任一条件就别用 DPM 了：
1. **需要实时**（30 FPS）：DPM 永远做不到
2. **类别多样**（>5 类）：训 DPM 一类要一天，YOLO 训一次全覆盖
3. **mAP 要求高**（>50%）：DPM 在 VOC 上最高 30%+，深度学习轻松 70%+
4. **不想折腾训练**：YOLO 预训练模型开箱即用
5. **移动端/嵌入式**：TFLite/NCNN 部署 MobileNet-SSD 比 DPM 快还准

## ⑫ DPM 留给深度学习的遗产

虽然 DPM 本身已不用于生产，但它的几个思想在现代检测器里仍然存在：

| DPM 思想 | 深度学习对应 |
|---|---|
| 根模板（整体） | RPN/Anchor 的 anchor 模板 |
| 部件模型 | 可变形卷积（DCN）、RoI Pooling 的局部区域 |
| 多 component / 多视角 | 多尺度 Anchor（Faster R-CNN 9 anchors） |
| BBox Regression | Fast R-CNN bbox reg → 所有检测器标配 |
| Hard Negative Mining | SSD/RetinaNet 的 focal loss 等价 |
| 滑动窗金字塔 | RPN 取代，思想延续 |
| HOG 特征 | CNN 底层特征自动学 HOG-like 响应 |

**学习 DPM 的真正意义**：不是为了用它，而是为了理解"检测为什么要考虑形变、为什么需要 anchor、为什么要做难样本挖掘"——这些是现代检测器的"思想地基"。
