# DPM 实战踩坑

## 坑 1：速度极慢，根本做不到实时

### 症状
- 一张 640×480 图检测几秒到十几秒
- 视频里跑 PPT 一样的帧率
- 嵌入式/移动端完全跑不动

### 根因
DPM 需要：
1. 计算**密集 HOG 金字塔**（每层 octave 8~10 层，每层都要做卷积）
2. **每个 component、每个尺度**都要跑根+N 个部件卷积
3. 每个部件还要做距离变换
4. Latent SVM 训练阶段更慢（几天）

即使作者后来做了级联加速（DPM Cascade），速度也只到几百毫秒/帧，仍然不够 30fps。

### 缓解办法
1. **缩图**：检测前把图缩到 320 宽，精度略降但速度能快 4 倍
2. **限制尺度范围**：设 minSize/maxSize，不跑所有尺度
3. **跳帧**：视频里每 3~5 帧检测一次，中间用跟踪器（KCF/MOSSE）延续
4. **用级联加速版**：voc-release5 之后作者出了 cascade DPM，速度提升 10~20 倍
5. **直接用深度学习检测**：YOLO 跑 CPU 都比 DPM 快 10 倍以上

## 坑 2：OpenCV 4.x 没有 DPMDetector

### 症状
```python
import cv2
cv2.dpm.DPMDetector_create(...)
# AttributeError: module 'cv2' has no attribute 'dpm'
```

### 根因
DPM 在 OpenCV 4.x 被移到 opencv_contrib 并最终删除（因为被深度学习方法取代）。

### 避坑
- 安装 OpenCV 3.4.x contrib：`pip install opencv-contrib-python==3.4.2.17`
- 或直接用 voc-release5（官方 C++/Matlab 实现）
- 或干脆用深度学习检测器（推荐）

## 坑 3：自己训练 DPM 困难重重

### 症状
- 训出来的模型 mAP 极低
- 部件位置发散，训练不收敛
- 训一次要一周

### 根因
DPM 训练对初始化、参数、数据顺序非常敏感，坑很多：
1. **根滤波器初始化**必须用 warp 到统一尺寸的正样本平均 HOG
2. **部件初始锚点**位置有讲究，放错了会导致局部最优
3. **难负样本挖掘轮数**不够会欠拟合，太多会过拟合
4. **C 参数**、**部件数量**、**component 数**都要调
5. **混合模型聚类**错误会把正样本分错 component

### 避坑（想自己训练）
1. 先跑通 voc-release5 在 PASCAL VOC 上的默认流程
2. 用官方脚本 `pascal_train.m` 做模板改自己的数据集
3. 类别一开始用 **1 个 component**，训通再加
4. 部件数从 6 开始，不要一开始就 8
5. 注意正负样本比例（正:负 ≈ 1:3~1:10）
6. 训练过程关注每个 stage 的 AP，如果下降就是发散了，回退上一轮

## 坑 4：部件数量不对导致过拟合/欠拟合

### 症状
- **部件数 = 2/3**：模型还是太硬，接近 HOG，形变容忍度不足
- **部件数 = 12+**：过拟合，检测慢，部件互相干扰

### 根因
部件数是 DPM 的关键超参：
- 太少：表达能力弱，形变容忍差
- 太多：参数暴增，训练样本不够会过拟合，且每个部件都要卷积/距离变换，速度慢

### 推荐值

| 类别 | 部件数 |
|---|---|
| 行人（最常见） | **8**（头/2 肩/2 髋/2 脚+躯干或类似配置） |
| 车辆 | 6~8 |
| 动物（猫/狗） | 8 |
| 刚性物体（瓶子/杯子） | 3~4 |

## 坑 5：尺度金字塔太粗导致漏检

### 症状
- 中远距离目标漏检
- 某些大小的物体反复漏

### 根因
默认金字塔间隔（每层缩放 1.058×，即每 octave 10 层）其实已经很密，但如果 scale 步进设太大（比如 1.2），某些尺寸会跳过。

### 避坑
- 检测时用 `interval=10`（每 octave 10 层，默认值）
- 特别小的目标：可以加 `interval=12~16`（更密但更慢）
- 或者多尺度测试：多次缩放图后检测，再合并

## 坑 6：不做 Bounding Box Regression，定位不准

### 症状
- 框要么大一圈要么小一圈
- 部分遮挡物体框偏

### 根因
根+部件的 HOG 匹配天然对齐到 cell 网格（8×8 像素），定位精度最多到 cell 级别。BBox 回归是后期版本加的精修步骤。

### 避坑
**训练时一定要开 bbox regression**（voc-release5 通过 `env.BBREG=1` 开启），检测时也要用回归后的框。

## 坑 7：上下文重扫（Context Rescoring）没开，置信度不准

### 症状
- 得分值分布奇怪，不同图之间阈值不可比
- 小物体得分虚高

### 根因
DPM 后期有一个"上下文重打分"机制：用根滤波器周围更大区域的 HOG 特征作为上下文，重新校准得分。没有这一步，分数在不同尺度/位置上不够稳定。

### 避坑
- 训练和检测都开启 rescoring
- 或者用更简单的方法：NMS 时只看相对排序（不卡绝对阈值）

## 坑 8：NMS 重叠阈值不对

### 症状
- 同一个物体出多个框（阈值太高）
- 相邻物体被吃掉一个（阈值太低）

### 根因
DPM 会在相邻尺度、相邻位置出很多重叠检测（尤其多 component 同时命中时），NMS 阈值影响很大。

### 推荐值

| 场景 | overlap 阈值 |
|---|---|
| 标准 | **0.3**（DPM 论文默认） |
| 密集物体（行人排队） | 0.5 |
| 稀疏场景 | 0.2~0.3 |

## 坑 9：类别不均衡，某些视角漏检

### 症状
- 正面行人检得好，侧面/背面漏
- 轿车正面能检，侧面不行

### 根因
单 component 只能覆盖一个视角。如果训练时某个视角样本少，混合模型可能聚类不出对应 component。

### 避坑
- 检查数据集中各视角样本数，不足时补数据或做翻转增强（左右翻转可以翻倍样本）
- 手动指定 component 数（比如行人至少 3 component）
- 检测侧脸时可以水平翻转图再检测一次（类似 Viola-Jones 的侧脸处理）

## 坑 10：Latent SVM 训练发散

### 症状
- 每轮训练 AP 不升反降
- 部件权重出现 NaN 或极端值
- 训练脚本崩溃

### 常见原因 & 解法
1. **数据未对齐**：正样本 bbox 尺寸差异大，warp 到统一大小时变形严重 → 检查 bbox 标注
2. **学习率/C 参数太大**：调小 C（从 0.001 开始）
3. **部件初始化乱**：用启发式规则（头顶、四肢位置）
4. **难负样本加太快**：每轮少加一点，控制负样本总数
5. **没有做 w 裁剪（w 截断）**：训练后期要做 PCA/权重裁剪，限制每个特征维度的权重范围

## 坑 11：和 HOG+SVM 比，提升有限

### 症状
同样的数据集上自己训 DPM，结果比 HOG+SVM 只高一点点，训练时间却多 10 倍。

### 根因
- 部件数太少（<4），或者部件初始位置不对
- 混合模型没开（只有 1 component）
- 训练轮数不够，Latent SVM 没收敛
- 类别本身是刚性物体（比如标志牌），部件形变空间小

### 判断是否值得用 DPM
- 物体是**非刚性**（人/动物/骑车人）：DPM 提升明显
- 物体是**刚性**（车/脸/标志）：用 HOG+SVM 或直接上深度学习

## 常见错误速查表

| 错误 | 原因 | 解法 |
|---|---|---|
| `module 'cv2' has no attribute 'dpm'` | OpenCV 4.x 移除了 dpm | 用 3.4.x 或官方 voc-release5 |
| 检测一张图 10 秒+ | 正常，DPM 就是慢 | 缩图/跳帧/换深度学习 |
| 训练 3 天不收敛 | Latent SVM 参数问题 | 检查初始化、降 C、减少部件 |
| 框不准、位置飘 | 没开 bbox regression | 开 BBREG=1 |
| 侧脸/特定视角漏 | component 数不够或聚类错 | 手动指定 component 数、补数据 |
| 所有框都被 NMS 掉了 | NMS 阈值太小/得分阈值太高 | overlap 调到 0.3，降阈值 |
