# 🔥 踩坑清单

## 坑 1：LBP 图一塌糊涂——忘了转灰度

彩色图直接进 LBP 是无意义的（而且很多库直接报错）。

> 🔧 修：必须 `cv2.cvtColor(img, COLOR_BGR2GRAY)`。

## 坑 2：光照不均 → 直方图分布塌缩

半边暗半边亮时，亮部全是 0/255，暗部噪声翻转 bit。

> 🔧 修：先做 CLAHE 直方图均衡 `cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8)).apply(gray)`。

## 坑 3：没归一化，直方图大小不一致

face 大小不一样直接拼直方图会导致距离不可比。

> 🔧 修：所有训练图先对齐+裁剪到固定大小（如 128×128）；每个 cell 直方图都 L1/L2 归一化。

## 坑 4：噪声导致 bit 翻转，特征全乱

单像素噪声翻转一个 bit，在 8 个 bit 里占 1/8，影响巨大。

> 🔧 修：
> - 先做一次小核高斯（`sigma=0.8`）；
> - 用 MB-LBP（区域均值对比）而不是单点对比；
> - 用 Uniform LBP（把大部分跳变多的"噪声模式"都归到一起了）。

## 坑 5：人脸对不齐，准确率掉成渣

LBP 对位置敏感——鼻子的 cell 和眼睛的 cell 不是一个分布。

> 🔧 修：必须先用 Haar/LBF 人脸关键点对齐，再裁到标准框（两眼距离 40 像素、眼在固定行）。

## 🚨 实战坑点补充

### 1. 不做 CLAHE 直接上 LBP = 送人头

如果图像一边亮一边暗（窗户逆光、闪光灯），同一张脸上"亮的那半"邻居都比中心亮、"暗的那半"邻居都比中心暗，LBP 密码直接错乱。**CLAHE 必须放在最前面**，参数 `clipLimit=2.0, tileGridSize=(8,8)` 是标准。

### 2. cell 大小不是越大越好

- **cell 太小（4×4）**：直方图稀疏（每个 cell 只有 16 个像素），统计不稳，识别率差；
- **cell 太大（32×32）**：空间位置精度丢失，变成"整坨平均"；
- **16×16 是 100×100 人脸的甜点**，对齐好的脸几乎都是这个值。

### 3. 归一化别用 L1，一定 L2-Hys

L1 归一化对大值（偶尔出现的强边缘）太敏感；L2-Hys 是 HOG 论文里提出的两步归一化（先 L2、裁剪到 0.2、再 L2），**对局部光照突变最鲁棒**。OpenCV 里用 `NORM_L2` 再手动 clip 也行。

### 4. 直方图距离用错 = 识别率掉 20%

直方图不是欧氏空间里的向量，而是**概率单纯形上的点**。距离度量必须用：
- **卡方距离**（χ²）：直方图匹配的金标准；
- **Hellinger 距离**（Bhattacharyya）：对小 bin 差异更敏感；
- **直方图相交**：快，但对非均匀光照鲁棒性差。
**绝对不要直接用欧氏距离**。

### 5. 对齐！对齐！对齐！

LBP 是拼 cell 的直方图，**人脸左右眼差 5 个像素，一个 cell 的内容就全换了**。必须先用人脸关键点对齐到两眼水平+固定尺寸（典型 100×100 两眼间距 40 像素），否则再好的特征也白搭。
