# 第 6 页 · 踩坑清单

## 新手最常掉的坑

### 坑 1：ORB 用 KD-Tree

::: danger 现象
二进制描述子用欧氏距离建 KD 树，语义完全不对，匹配稀烂。
:::

::: tip 解决
二进制描述子一律用 FLANN_INDEX_LSH + NORM_HAMMING。
:::

### 坑 2：checks 设太小

::: danger 现象
比如设成 2，近似过猛，好匹配也被漏掉。
:::

::: tip 解决
从 50 起步，按匹配数调整，通常 50~100。
:::

### 坑 3：忘记比率测试

::: danger 现象
没有 Lowe 比率，误匹配会淹没正确匹配。
:::

::: tip 解决
knnMatch(k=2) 后按 0.75~0.8 比率过滤。
:::

### 坑 4：特征点很少也用 FLANN

::: danger 现象
几百个点时索引开销大于收益。
:::

::: tip 解决
点数少时改回 BFMatcher，更准也够快。
:::

## 通用调试四步法

1. **可视化中间结果**——不要只盯最终输出，把每一步的中间图都存下来看
2. **先小图后大图**——拿 200×200 的简单图跑通，再上真实场景大图
3. **先默认值后调参**——有 baseline 再改，一次只改一个参数
4. **对齐参考实现**——用 OpenCV 官方 tutorial 的结果做基准，差异大就查原因

## 自查清单

- [ ] 数据类型对不对？（uint8 vs float32 差别巨大）
- [ ] 通道顺序对不对？（BGR vs RGB、灰度 vs 彩色）
- [ ] 图像是否归一化？（0–255 vs 0–1）
- [ ] 边界是否处理？（图像边缘的卷积/插值）
- [ ] 参数单位对不对？（像素 vs 比例、毫秒 vs 秒）
