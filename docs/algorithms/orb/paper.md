## 写作动机：专利害死人

> We propose a very fast binary descriptor based on BRIEF, called ORB ... that is **rotation invariant and immune to the patent encumbrances of SIFT and SURF**.

作者开门见山——**SIFT 和 SURF 都有专利**，Willow Garage 作为 ROS/OpenCV 的娘家，要给机器人社区一个**真·免费可用**的特征点。

当时（2011）的状态：
- **SIFT**（2004）：精度高但慢，专利保护
- **SURF**（2006）：快 3 倍，专利保护
- **FAST**（2006）：角点检测超快，但**没有描述子、没有方向、没有尺度**
- **BRIEF**（2010）：二进制描述子超快，但**没有旋转不变、没有尺度、不抗噪**

ORB 的目标：**把 FAST 和 BRIEF 改造、组合起来，做成一个免费、快、有尺度+旋转不变的完整方案**。

## 两大核心创新

### 创新 ①：oFAST（带方向的 FAST）

FAST 本身是判断"Bresenham 圆（半径 3 的 16 像素圆）上是否有连续 N 个点都比中心亮/暗"，但它**不带方向**、**不带尺度**。

ORB 做了两件事让 FAST "升级"：

**（1）用图像金字塔提供尺度**

不是像 SIFT/SURF 那样建连续尺度空间，而是简单地**把图像降采样到不同层**（每层 scaleFactor 倍，默认 1.2），每层都跑 FAST。粗糙但快。

**（2）用"灰度质心法"算主方向（Intensity Centroid）**

比 SIFT/SURF 的 36 bin 梯度直方图**快很多**：

$$
C = \left(\frac{m_{10}}{m_{00}}, \frac{m_{01}}{m_{00}}\right),\quad m_{pq} = \sum_{x,y} x^p y^q I(x,y)
$$

其中 C 是**灰度加权的质心**（越亮的像素权重越大），从角点指向质心的向量方向就是主方向：

$$
\theta = \operatorname{atan2}(m_{01}, m_{10})
$$

只需要算图像矩，O(1)，比直方图法快一个数量级。

### 创新 ②：rBRIEF（rotated BRIEF，旋转不变的二进制描述子）

#### 先讲 BRIEF 是什么
BRIEF 在关键点周围按某种随机分布选 N 对点（N=256），每对点比较"第一点亮还是第二点亮"，亮记 1、暗记 0，拼成一个 **256 bit** 的二进制串。

汉明距离（Hamming Distance）——两个串**不同 bit 的个数**——就是相似度，用 XOR + POPCNT（CPU 内置指令）算，**一个时钟周期能比几十位**。

但 BRIEF 有个大问题：**图像一旋转，选的点对就歪了，描述子完全对不上**。

#### rBRIEF 的解决方案：学习一组"抗旋转"的点对

1. 先从 PASCAL VOC 2006 数据集里抽 ~30 万张图像块
2. 对每个块，按随机采样生成约 20 万个候选点对
3. 对每个点对在**各种旋转角度**下算其相关性（τ 值方差、相关性均值）
4. 用贪心算法选 256 个点对，满足：
   - （a）所有点对之间相关性尽可能**低**（方差大，区分度高）
   - （b）每个点对的 0/1 均值尽量接近 **0.5**（一个 test 给出最大 1 bit 信息量）
   - （c）点对分布**尽量覆盖整个 patch**（不是集中在中心）
5. 再把这 256 个点对**按关键点主方向 θ 做旋转**（乘以旋转矩阵 R_θ），生成实际要比较的点位置

**结果**：rBRIEF 在图像旋转到 ±30° 甚至更大角度时，仍然保持高识别率。

### 补充：FAST 角点加了 Harris 响应排序

FAST 出点太多扎堆，ORB 会在每个 level 上保留响应最强的 N 个（用 Harris 角点响应作为评分），并按金字塔均匀分布，防止所有点都集中在某一层。

## 速度对比（论文原表摘要）

| 算法 | 检测+描述 | 匹配 1000 对 | 备注 |
|---|---|---|---|
| SIFT | 5220 ms | 28.3 ms | 浮点 128 维 |
| SURF | 2170 ms | 18.9 ms | 浮点 64 维 |
| ORB | **15.3 ms** | **2.7 ms** | **二进制 256 bit** |

ORB 比 SIFT **快两个数量级**，比 SURF 快 ~100 倍。这是它能统治实时场景的核心原因。

## 论文的关键 takeaway

1. **"二进制描述子 + Hamming 距离 = 实时"**：浮点描述子的欧氏距离计算昂贵，二进制异或极快
2. **"方向可以用图像矩，不需要梯度直方图"**：灰度质心法 O(1) 给方向，比 SIFT 快得多
3. **"学习一个好的点对集合"比"随机点对"鲁棒得多**：rBRIEF 不是简单旋转 BRIEF，而是重新学了一组抗旋转的点对
4. **"免费"比"最强"更能占领市场**：因为专利问题，SURF/SIFT 在 2010 年代商用受限，ORB 借 OpenCV 之手直接变成事实标准

## 局限

1. **尺度不变性弱**：靠图像金字塔（离散层），不是 SIFT 的连续尺度空间，尺度跳变超过一个 octave 容易漏
2. **旋转不变性有限**：论文里主要验证到 ±30°，大角度（>60°）匹配率下降
3. **描述子不如 SIFT 精确**：二进制 256 bit 信息量比浮点 128 维小（256 bit = 32 字节，128 float = 512 字节）
4. **FAST 对边缘敏感**：阈值不够高时会在边缘线上出点，需要 Harris 过滤后处理
