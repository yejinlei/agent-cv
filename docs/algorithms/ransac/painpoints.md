# 实战踩坑 · RANSAC

> RANSAC 的坑有个共同特征：**它永远不会报错，只会默默给你一个错的模型**。
> 这一页收 10 个最常遇到的坑，每条按「症状 → 根因 → 解法」写。

## 坑 1：阈值单位搞错，全部点都成了内点

**症状**：跑完 RANSAC，`mask` 里全是 1，或者内点数等于总点数，
算出的 H 就是个近似单位矩阵。

**根因**：`ransacReprojThreshold` 的单位**跟着输入坐标的单位走**。
你把特征点归一化到 $[0, 1]$ 了，却照抄了「3.0 像素」的阈值——
这相当于允许 3 个图像宽度的误差，当然什么点都算内点。

**解法**：**先用像素坐标做 RANSAC，最后再考虑归一化**。
若确实要在归一化坐标下跑，阈值同步除以图像宽度（如 3 px / 1000 ≈ 0.003）。

```python
# 错误：坐标已归一化，阈值却是像素量级
# H, mask = cv2.findHomography(pts_norm_src, pts_norm_dst, cv2.RANSAC, 3.0)

# 正确：像素坐标 + 像素阈值
H, mask = cv2.findHomography(pts_px_src, pts_px_dst, cv2.RANSAC, 3.0)
```

## 坑 2：丢掉 mask，等于白跑

**症状**：拿到了 H，但没管 mask，后面用全部匹配点做拼接/重建，结果一团糟。

**根因**：RANSAC 的价值一半在「模型」，一半在「谁是内点」。
`mask` 就是它筛出来的可信匹配，很多人只取 `H` 而丢掉 `mask`。

**解法**：永远把两者一起取出来，用 `mask` 保留下一步要用的点。

```python
H, mask = cv2.findHomography(src, dst, cv2.RANSAC, 3.0)
src_in, dst_in = src[mask.ravel() == 1], dst[mask.ravel() == 1]
```

## 坑 3：忘了重拟合，精度上不去

**症状**：模型大致对，但精度只有几个像素，做亚像素任务不够。

**根因**：RANSAC 主体只用 $s$ 个点拟合（单应就 4 个点），
命中即止，精度受限于这 4 个点的定位噪声。

**解法**：用找出的内点**再做一次最小二乘**。OpenCV 的 `findHomography`
内部已包含这一步，但手写实现里最容易漏。

## 坑 4：最小样本退化，解出矩阵爆炸

**症状**：偶尔某轮迭代后模型数值巨大，或者直接 `nan`。

**根因**：抽到的 4 个点里有 3 个近似共线（解单应），或 2 个点几乎重合（解直线）。
这些配置下方程组秩亏，解不稳定。

**解法**：采样后立刻做退化检测并跳过该轮（见 [源码走读](/algorithms/ransac/source) 的 `collinear` 函数）。

## 坑 5：外点率超过 50%，标准 RANSAC 崩了

**症状**：内点率很低时，跑很多次都找不到正确模型，或者结果每次都不一样。

**根因**：$k = \log(1-p)/\log(1-w^s)$，$w$ 一低，所需迭代次数指数级上升；
$w=20\%$ 时单应矩阵要 1000+ 次，`maxIters` 若设小了根本跑不到。

**解法**（三选一）：
1. **先提内点率**：用 Lowe 比值检验、交叉验证、极线约束预筛一遍；
2. **换更强的方法**：`cv2.LMEDS` 或 `cv2.USAC_MAGSAC`；
3. **换 PROSAC**：按匹配质量排序采样，好点优先。

## 坑 6：模型选错，用 H 去解非平面场景

**症状**：场景里有明显的前后景深，却硬用单应矩阵，结果内点率很低、
重投影误差很大。

**根因**：单应矩阵只在**平面场景**或**纯旋转**下成立，
非平面场景必须用基础矩阵 F / 本质矩阵 E。

**解法**：同时求 H 和 F，比较内点率和重投影误差再决定用哪个
（详见 [调参技巧](/algorithms/ransac/tricks) 的「H 还是 F」一节）。

## 坑 7：随机种子不固定，结果不可复现

**症状**：同样的输入，跑两次得到的模型略有不同，线上排查困难。

**根因**：RANSAC 本质是随机采样算法，未固定种子时每次抽样顺序不同。

**解法**：固定 `np.random.seed(...)`；或接受随机性，但在 RANSAC 后
统一做一次最小二乘精化，把随机抖动熨平。

## 坑 8：`maxIters` 设太大，白白浪费时间

**症状**：一帧耗时很高，但结果是稳定的——说明其实早就收敛了。

**根因**：把 `maxIters` 设成几千，而实际内点率很高，几十次就够。

**解法**：把 `confidence` 调对（0.99~0.995），让自适应迭代次数的机制
自己提前停；`maxIters` 只当作「兜底上限」。

## 坑 9：拿 mask 的形状当布尔用

**症状**：`if mask:` 永远为真，或者索引报 shape 错误。

**根因**：`mask` 是 `(N, 1)` 的 uint8 数组，不是布尔向量。

**解法**：用 `mask.ravel() == 1` 转换，或 `mask.flatten().astype(bool)`。

## 坑 10：用 RANSAC 做不该它做的事

**症状**：想用 RANSAC 直接估计一个「高参数模型」（如高次多项式、
非参数形变场），结果慢得离谱且不稳定。

**根因**：最小样本数 $s$ 随参数个数增长，抽到全内点的概率是 $w^s$，
$s$ 一大就崩。

**解法**：RANSAC 只适合**低参数、能用少量点确定**的模型
（直线、圆、H、F、E、PnP、刚体变换）。高参数模型应换
最小中值、M 估计或带正则的最小二乘。

## 一页速记

| 坑 | 一句话解法 |
|---|---|
| 阈值单位错 | 坐标与阈值同单位，像素配像素 |
| 丢 mask | `H` 和 `mask` 一起拿 |
| 不重拟合 | 内点再做一次最小二乘 |
| 样本退化 | 采样后查共线/重合 |
| 外点率过高 | 先预筛，或换 LMedS / PROSAC |
| 模型选错 | 平面用 H，非平面用 F/E |
| 随机不可复现 | 固定种子 + 后置重拟合 |
| 迭代次数浪费 | 靠 confidence 自适应收敛 |
| mask 用法错 | `mask.ravel() == 1` |
| 模型太复杂 | 只给低参数模型用 RANSAC |
