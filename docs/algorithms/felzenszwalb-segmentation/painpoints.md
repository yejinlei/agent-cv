# 第 6 页 · 踩坑清单

## 新手最常掉的坑

### 坑 1：k 设太小

::: danger 现象
区域阈值过低，图像被切成几百个碎块。
:::

::: tip 解决
从 k=100 起步逐级加大，直到区域数合理。
:::

### 坑 2：忘记 min_size

::: danger 现象
大量 1~2 像素的小区域混在结果里。
:::

::: tip 解决
min_size 按图像尺寸设，一般 20~100。
:::

### 坑 3：直接上原图

::: danger 现象
噪声会让边权抖动，影响合并。
:::

::: tip 解决
先做 σ=0.8 高斯平滑，论文默认如此。
:::

### 坑 4：期望像素级边界

::: danger 现象
该方法是区域级分割，边界不精确。
:::

::: tip 解决
需要精细边界时配合 GrabCut 或边缘引导滤波。
:::

## 通用调试四步法

1. **可视化中间结果**——不要只盯最终输出，把每一步的中间图都存下来看
2. **先小图后大图**——拿 200×200 的简单图跑通，再上真实场景大图
3. **先默认值后调参**——有 baseline 再改，一次只改一个参数
4. **对齐参考实现**——用 OpenCV 官方 tutorial 的结果做基准，差异大就查原因

## 自查清单

- [ ] 数据类型对不对？（uint8 vs float32 差别巨大）
- [ ] 通道顺序对不对？（BGR vs RGB、灰度 vs 彩色）
- [ ] 图像是否归一化？（0–255 vs 0–1）
- [ ] 边界是否处理？（图像边缘的卷积/插值）
- [ ] 参数单位对不对？（像素 vs 比例、毫秒 vs 秒）
