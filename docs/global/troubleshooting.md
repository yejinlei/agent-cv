# 故障排查手册 · 症状 → 原因 → 修复

> 传统 CV 项目中 90% 的问题都不是"算法不适合"，而是**参数、光照、标定、预处理**出错。
> 这一页按"症状"组织——看到什么现象，先怀疑什么、按什么顺序排查。

::: tip 用法
1. 先在下面的字母分类里找到你最接近的"症状"
2. 按"排查顺序"从前往后查，通常第一个命中就是问题所在
3. 修复后重跑，如果还不行，下一条
:::

---

## A. 二值化 / 阈值类

### A1. 阈值出来全白或全黑
- **原因 1**：固定阈值不适合当前光照（最常见）→ 换成 Otsu 或自适应阈值
- **原因 2**：图像没做白平衡/曝光补偿 → 先调采集端曝光/增益
- **原因 3**：相机进入自动曝光模式，帧间亮度跳 → 锁曝光/锁白平衡
- **原因 4**：镜头进灰/光源老化 → 清洁镜头、换光源
- **排查命令**：`cv2.meanStdDev(img)` 看均值是不是靠近 0 或 255

### A2. Otsu 分割出来边缘碎
- **原因 1**：图像不是"双峰直方图" → 改用自适应阈值
- **原因 2**：噪点太多 → 先高斯/双边滤波再 Otsu
- **原因 3**：前景占比太小/太大（<10% 或 >90%）→ Otsu 假设不成立，手动给 T 或用分块阈值

### A3. 自适应阈值出来全是噪点
- **原因 1**：blockSize 太小 → 调大（从 31 起试）
- **原因 2**：C 常数太小 → 调大（从 5 起）
- **原因 3**：没有先模糊 → 先高斯(5,5)再自适应阈值

## B. 边缘检测类

### B1. Canny 出边全是碎段、连不起来
- **原因 1**：高阈值太高 → 降低 threshold2
- **原因 2**：低阈值太高 → 降低 threshold1（推荐 1:2 或 1:3）
- **原因 3**：图像没去噪 → 先双边滤波或高斯模糊
- **原因 4**：光照不均匀 → CLAHE 均衡后再 Canny

### B2. Canny 出边太多、假边泛滥
- **原因 1**：阈值太低 → 提高 threshold2 到 80~120
- **原因 2**：apertureSize 太大（默认 3，5 会更敏感）
- **原因 3**：图像未做 ROI 裁剪 → 背景复杂区域直接裁掉

### B3. Sobel 边缘粗到 3~5 像素
- **正常现象**：Sobel 本就出粗边，要细边必须 Canny+NMS

## C. 形态学 / 连通域类

### C1. 形态学后小目标消失了
- **原因**：开运算核太大 → 减小核尺寸（用 3×3 起步）
- **修复**：用 `cv2.morphologyEx(img, MORPH_OPEN, kernel, iterations=1)`，核不要大于目标最小宽度

### C2. 断开的线怎么都连不上
- **原因 1**：膨胀不够 → 用矩形核多迭代几次
- **原因 2**：间隙太大（>5 像素）→ 形态学不适合，改用形态学梯度+自适应连接，或 Hough 直线

### C3. 连通域数量爆炸
- **原因 1**：噪点太多被当成独立区域 → 先开运算去噪
- **原因 2**：area 筛选没做 → 用 `connectedComponentsWithStats` 过滤面积小于阈值的

## D. 特征点检测类

### D1. Harris/Shi-Tomasi 检测到的点都在边缘上
- **原因**：qualityLevel 太低 / minDistance 太小 → 提高 qualityLevel（0.01 起），加大 minDistance
- **修复**：`goodFeaturesToTrack(maxCorners=500, qualityLevel=0.01, minDistance=10)`

### D2. FAST 点多如牛毛但没法匹配
- **正常**：FAST 没有描述子、没有方向、没有尺度，直接拿 FAST 点做匹配必错
- **修复**：要匹配请用 ORB（带 oFAST + rBRIEF）

### D3. SIFT/SURF 点太少
- **原因 1**：contrastThreshold 太高 → 降到 0.01~0.03
- **原因 2**：nFeatures 限太少 → 调高（默认 0 表示不限）
- **原因 3**：图像太模糊/太光滑（如白墙）→ 不是算法问题，是场景问题

### D4. ORB 点多但匹配错配率高
- **原因 1**：没开 crossCheck / ratio test → BF 匹配后做 Lowe 比率检验（0.75）
- **原因 2**：没做 RANSAC → 单应矩阵/基础矩阵 RANSAC 剔除外点
- **原因 3**：patchSize 太小，大尺度下特征不稳定 → 增大 patchSize（默认 31）

---

## E. 特征匹配 / 拼接类

### E1. 匹配结果全是错对
- **原因 1**：两图差异太大（尺度/旋转/视角）→ 用 SIFT/ORB 这种具有不变性的
- **原因 2**：没做比率检验 → `knnMatch(k=2)` 后 `m.distance < 0.75 * n.distance` 过滤
- **原因 3**：外点没剔 → RANSAC 算单应/基础矩阵做几何验证

### E2. 图像拼出来错位/鬼影
- **原因 1**：单应矩阵算错（外点太多）→ RANSAC 阈值调到 3~5 像素
- **原因 2**：相机位姿不是纯旋转（有视差）→ 不能用单应拼接，要用基础矩阵+三角化或柱面/球面投影
- **原因 3**：曝光差异 → 拼接前做白平衡/羽化融合

## F. 光流类

### F1. LK 光流点很快跑丢
- **原因 1**：winSize 太小 → 增大（15,15 起试到 31,31）
- **原因 2**：没开金字塔 → `maxLevel=3~4`
- **原因 3**：运动太大 → 提高帧率或用金字塔+Farnebäck 稠密
- **原因 4**：点选在边缘上了 → 用 Shi-Tomasi（qualityLevel≥0.01）

### F2. Farnebäck 稠密光流全是噪点
- **原因 1**：图像没去噪 → 先高斯
- **原因 2**：pyr_scale 太激进（默认 0.5，太快会失败）→ 用 0.5 保证 5 层金字塔
- **原因 3**：poly_n/poly_sigma 不匹配 → poly_n=5, poly_sigma=1.1 默认即可

---

## G. 立体 / 深度类

### G1. SGBM 视差图全黑/全白
- **原因 1**：numDisparities 范围错了（必须是 16 的倍数）→ 从 minDisparity=0, numDisparities=16*N 试
- **原因 2**：blockSize 太小 → 用 5~11 的奇数
- **原因 3**：相机没做极线校正 → 必须先 `stereoRectify` + `initUndistortRectifyMap`

### G2. 视差图有明显条纹/噪点
- **原因 1**：P1/P2 不合适 → 按公式 P1=8×channels×blockSize², P2=32×channels×blockSize²
- **原因 2**：uniquenessRatio 太小 → 调到 5~10
- **原因 3**：没做 speckle 过滤 → speckleWindowSize=100, speckleRange=2

### G3. 立体深度不准
- **原因 1**：标定误差 > 0.5 像素 → 重新标定，拍 20+ 张不同角度棋盘
- **原因 2**：baseline 太短测不远 / 太长近处看不见 → 按工作距离选 baseline（约为工作距离 1/10~1/20）
- **原因 3**：没做 WLS 后处理 → `ximgproc.createDisparityWLSFilter`

## H. 分割类

### H1. Watershed 结果全是"马赛克"（过分割）
- **原因 1**：直接跑没给 marker → 必须做标记控制（marker-controlled）
- **修复**：先用阈值/形态学/距离变换找前景/背景标记，再 `watershed(markers)`

### H2. GrabCut 抠出来边缘是锯齿
- **原因 1**：没做边界 matting → 用 `GC_INIT_WITH_MASK` 手动圈出"可能前景"
- **原因 2**：迭代次数不够 → iterCount 加到 5~10
- **原因 3**：rect 圈得太贴边缘 → rect 留 5~10 像素边距

### H3. GrabCut 把背景部分也抠进来了
- **原因 1**：前景背景颜色太接近 → 手动在 mask 里标记 BG/FG
- **原因 2**：GMM 组件数不够 → nCount=5 起试
- **原因 3**：这场景根本不适合 GrabCut（如透明、发丝）→ 用深度学习抠图

### H4. K-Means 颜色量化后颜色偏色
- **原因 1**：颜色空间用了 BGR → 必须转到 Lab 或 HSV
- **原因 2**：K 太小 → 增大 K
- **原因 3**：初始化不好 → `KMEANS_PP_CENTERS` 而不是随机

## I. 目标检测类

### I1. Viola-Jones 人脸误检太多
- **原因 1**：minNeighbors 太小 → 调到 4~6
- **原因 2**：scaleFactor 太接近 1 → 调到 1.1~1.2
- **原因 3**：minSize 太小 → 按实际人脸大小设 minSize

### I2. Viola-Jones 漏检
- **原因 1**：minNeighbors 太大、scaleFactor 太大 → 放宽
- **原因 2**：侧脸/非正面 → V-J 只检正面，侧脸用 DPM 或深度学习
- **原因 3**：没开金字塔或 flags 没设

### I3. HOG+SVM 行人误检多
- **原因 1**：没做难负例挖掘 → 把误检样本加入负样本重训 SVM
- **原因 2**：hitThreshold 太低 → 调高（默认 0，调到 0.3~1）
- **原因 3**：scale 步长太大/太小 → winStride/padding 调整

## J. 3D / 位姿 / 配准类

### J1. solvePnP 位姿飘
- **原因 1**：3D-2D 对应点有外点 → 用 `SOLVEPNP_EPNP` 或 `SOLVEPNP_ITERATIVE` 配合 RANSAC flag
- **原因 2**：畸变系数没传 → 必须先 `undistortPoints` 或传 distCoeffs
- **原因 3**：点都共面 → 平面 PnP 退化，增加非共面点

### J2. ICP 越配越飞
- **原因 1**：没有初值 → **ICP 必须有初值**！先粗配（FPFH+RANSAC/SAC-IA）再精配 ICP
- **原因 2**：两帧重叠率太低（<30%）→ 加大重叠或换更好的特征
- **原因 3**：没做离群点去除 → 先 `StatisticalOutlierRemoval`
- **原因 4**：用了点到点 ICP，建议点到面 PointToPlane 更快收敛

### J3. 标定重投影误差 > 1 像素
- **原因 1**：拍的图太少（<10 张）→ 至少 20 张，覆盖四角、不同倾角
- **原因 2**：标定板没贴平/起皱 → 换玻璃/铝制标定板
- **原因 3**：角点检测不准 → 用 `findChessboardCornersSB`（比默认准），加亚像素
- **原因 4**：运动模糊/曝光不对 → 重新采图

## K. 性能 / 部署类

### K1. 同样算法 C++ 比 Python 慢
- **原因**：用了 Debug 编译，没开 -O2/-O3；或者链接了 Debug 版 OpenCV
- **修复**：用 Release 模式重编译

### K2. OpenCV 启动就占几百 M 内存
- **原因**：编译进了所有模块（dnn/cuda等）→ 只编译用到的模块；或用 `cv2.utils.filesystem` 查看加载项

### K3. 嵌入式上 OpenCV 跑起来比 PC 慢 10 倍
- **原因**：没开 NEON/VFPV3 → 重新编译 `-DENABLE_NEON=ON -DENABLE_VFPV3=ON`
- **修复**：必要时上 Tengine/NCNN 做推理加速

## L. 快速诊断卡（按频率排序）

如果不知道从哪下手，按这个顺序查，**70% 的问题在前 3 步解决**：

1. **光/曝光**：直接看原图是不是暗了/糊了/闪了 → 硬件问题优先
2. **畸变/几何**：是不是镜头畸变没校、外参变了 → 标定问题
3. **阈值/参数**：同一个算法换个参数能否救 → 参数问题
4. **预处理**：是不是没去噪、没白平衡、没转色彩空间 → 预处理
5. **后处理**：是不是没做 NMS/形态学/RANSAC → 后处理
6. **算法选择**：是不是根本选错算法了 → 回 [选型决策树](/global/choose-algorithm)
7. **场景问题**：目标变了、新类型出来了 → 回数据流第 8 环节监控
